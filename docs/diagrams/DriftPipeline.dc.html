07 · Drift monitoring

From a one-shot check to a scheduled sweep

A named check keeps its monitor alive so a background worker can re-evaluate it and persist a baseline.

Request path
POST /v1/drift/check{reference, window, name?} with at least 30 window samples, else 409.
▼
DriftMonitor(reference)Observes each window value, then check(): PSI with bias correction, KS gated on significance.
▼
Level: ok, warn or alertResponse carries psi, psi_adjusted, ks, ks_pvalue, n.
▼ only when name is given
state.drift_monitors[name]The monitor persists across calls. Without a name the endpoint stays a pure one-shot check.
Worker path (drift-evaluation, every 300 s)
drift_evaluation_tickIterates every named monitor: monitor.check().
▼ level not ok
OpsRepo.upsert_drift_baselineStores list(window) as the new baseline. A deque is rejected by OpsRepo, so the tick converts it.
▼ 30 or more observations
DriftWindowFrame (pandas)Pairs each observation with its position, then builds rolling PSI and a daily summary into drift_frame_reports[name].
Reading the pandas report honestly Rolling PSI uses a 200-sample window by default, so with a shorter series the tail is NaN. Positions stand in for timestamps because the monitor does not record them, which puts a short demo series into one daily row.
