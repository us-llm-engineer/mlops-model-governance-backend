08 · Incidents

Open, work the checklist, escalate, resolve

Routes exist only because the incidents extension is now mounted at startup. The escalation worker uses a listing method added for it.

POST /v1/incidents{title, signal}. The signal is classified into a severity with a response deadline.
POST .../stepsChecklist steps must be completed in order, otherwise 409.
GET /v1/incidents/{id}Returns a copy of the record, tier included.
POST .../resolveNeeds every checklist step done first; P0 and P1 also need a complete postmortem. Resolved incidents no longer escalate.
Severity rules, in priority order
P0 serving_failure or null_predictions
P1 accuracy_drop_pct above 10
P2 feature_psi above 0.3 or drift_level alert
P3 any other reported condition

incident-escalation worker, every 60 s incident_escalation_tick(manager) lists open incident ids, reads each tier before, calls escalate_if_overdue(id), and counts the incidents whose tier rose.
