06 · Policy

Publish, activate, decide; casbin checks it in tests

The raw PolicyDecisionPoint makes every decision. casbin is a test-time oracle and is never imported by the server.

Online path (HTTP)
POST /v1/policy/publishAdmin only. A bundle of rules becomes a numbered version in the PolicyStore. Rule scope (action, resource) is validated. Audited.
▼
POST /v1/policy/{version}/activateLoosening, including narrowing a rule's scope, needs human_approved_by, else PolicyDenied.
▼
POST /v1/policy/decidePolicyDecisionPoint.decide(action, context): a rule applies when its action and resource scope match (casbin keyMatch). Every applicable block rule must pass; warn never blocks; empty bundle and any error deny.
▼
Audit entryAction policy.{action}, resource from context["resource"] or the action name, plus policy hash and failed rule ids.
Test-time oracle (pytest, no server)
tests/test_policy_vs_casbin_oracle.pySeeded random bundles and contexts: 3 seeds x 3,600 decisions.

▼

Proof it bitesThree deliberately broken engines (max_metric off by one, scope ignored, warn treated as block) must each be caught.
What changed, and what has not The old adapter translated only role_in rules, treated "*" as a literal, and disagreed with the layer on 3 of 8 demo requests. Scope now lives in the layer and the oracle covers every kind. Production transitions and rollback are now gated by the active policy (on by default; no active policy denies). Policy versions are written to the ops database and reloaded on start.
